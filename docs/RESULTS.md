## Evidence, risk by risk

### 1. Unauthenticated Access

Attack: call without a hello; hello signed with the wrong key; a rogue gateway answering the agent

- Plain MCP: call succeeds (MCP stdio has no authentication)
- Paper design: **blocked**. no hello -> no authenticated SMCP session on this connection (the client sent no smcp/hello); impersonation -> SMCP authentication failed: the hello signature does not verify against the registered key of report; rogue gateway -> the serverHello signature does not verify against the registry. Control: 4.2 mutual authentication.
- With extensions: **blocked**. no hello -> no authenticated SMCP session on this connection (the client sent no smcp/hello); impersonation -> SMCP authentication failed: the hello signature does not verify against the registered key of report; rogue gateway -> the serverHello signature does not verify against the registry. Control: 4.2 mutual authentication.

### 1. Session Management Flaws

Attack: replay a captured call; reuse it on another connection; forge a MAC; use an expired session

- Plain MCP: replayed call executes twice
- Paper design: **blocked**. replay -> replayed or out-of-order call (seq 1, last accepted 1); other connection -> the envelope is bound to a different session; forged MAC -> the envelope MAC does not verify with this session's key; expired -> the SMCP session has expired; open a new session. Control: 4.2 session binding, per-call MAC and seq.
- With extensions: **blocked**. replay -> replayed or out-of-order call (seq 1, last accepted 1); other connection -> the envelope is bound to a different session; forged MAC -> the envelope MAC does not verify with this session's key; expired -> the SMCP session has expired; open a new session. Control: 4.2 session binding, per-call MAC and seq.
